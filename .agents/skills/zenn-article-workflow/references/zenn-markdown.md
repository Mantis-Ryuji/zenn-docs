# このリポジトリで使う Zenn 記法

2026-09-28 に [Zenn Markdown 公式ガイド](https://zenn.dev/zenn/articles/markdown-guide)、[CLI 公式ガイド](https://zenn.dev/zenn/articles/zenn-cli-guide)、[GitHub画像管理](https://zenn.dev/zenn/articles/deploy-github-images) を確認。細かな仕様が変わった場合は公式を再確認する。

## Frontmatter と見出し

```yaml
---
title: "記事の中心的な問いを表すタイトル"
emoji: "📘"
type: "tech"
topics: ["機械学習", "深層学習"]
published: false
---
```

`type` は内容に応じて `tech` または `idea`、topics は最大5つ。既存記事の種類やemojiを機械的に変えない。公開フラグは `published` であり、`publish` ではない。公開予約用の設定を自動で足さない。

本文は `## 1. はじめに` から `## 6. さいごに`。節は `### 2.1 ...` の形で、第2〜5章は各3節まで。タイトルを本文のH1や余分なH2として再掲しない。公式も本文見出しをH2から始めることを推奨している。

## KaTeX と導出

インライン数式は `$x \in \mathbb{R}^d$`。独立した式は、前後に空行を入れた `$$` ブロックに書く。

```markdown
期待値が存在する確率変数 $X$ に対し、$\mu=\mathbb{E}[X]$ とする。
二次モーメントも有限であれば、分散は次のように展開できる。

$$
\begin{aligned}
\operatorname{Var}(X)
&= \mathbb{E}[(X-\mu)^2] \\
&= \mathbb{E}[X^2-2\mu X+\mu^2] \\
&= \mathbb{E}[X^2]-2\mu\mathbb{E}[X]+\mu^2 \\
&= \mathbb{E}[X^2]-\mu^2.
\end{aligned}
$$

2行目では二乗を展開し、3行目では期待値の線形性と $\mu$ が定数であることを使った。
```

必要な箇所では `aligned`、`cases`、行列環境、`\underbrace`、`\tag{1}` などを使える。記事内で数式番号を使う場合は重複と参照を確認する。論文の `\label` / `\ref` や独自マクロを、そのままZennで使えると仮定しない。KaTeXはLaTeX全体ではないので [対応関数](https://katex.org/docs/supported.html) を確認する。

式の長さは意味の切れ目で折り返す。スクリーンショット化して導出を読みにくくしない。LaTeXの区切り `\(...\)` / `\[...\]` を新しく使わず、`$` / `$$` に統一する。ただし `\\[4pt]` のような改行・間隔指定まで誤って置換しない。

## 本文・補足・注意の役割を分ける

```markdown
:::message
この導出では、候補モデルが同じパラメータ対応を共有すると仮定する。
:::

:::message alert
この実験での改善は、任意の初期値から得たモデルを平均できる保証ではない。
:::

:::details 二次項を残した展開
途中計算をここへ残す。本文には、この計算の前提と結論を置く。
:::
```

`message` は押さえるべき前提や解釈、`alert` は誤解しやすい限界、`details` は長い補助計算に使う。本文を理解するための核心を全部折りたたみに押し込まない。入れ子が必要なら、外側を `::::details ...` と `::::`、内側を `:::message` と `:::` のように区別する。

## 出典・図・コード

- 主論文と公式実装：独立した行の `@[card](https://...)`。関連する理由を本文に書く。
- 個別の根拠・補足：本文の `[^paper]` と、`[^paper]: 著者・年・[論文名](https://...)`。同一文献の脚注IDを重複定義しない。
- 画像：`![代替テキスト](/images/zenn/article-slug/fig-01.png =700x)`。幅指定は必要なときだけ使う。
- キャプション：画像の直下に `*Fig.1：比較内容・条件・出典。*`。本文でもその図が何を示すか説明する。
- コード：言語名を付け、必要なら開始フェンスを ```` ```python:example.py ```` のようにしてファイル名も示す。長い補助実装はdetailsへ置ける。
- 表：手法の前提・保証・費用など同じ軸で比べたいときに使う。長い数式や段落を無理にセルへ詰めない。
- Mermaid：小さな処理フローには `mermaid` フェンスを使える。Zennでは1ブロック2,000文字、フローチャートの `&` は10個以下という制限がある。数理プロットは描画ツールで別途生成する。

既存の外部画像URLも利用できる。ローカル画像の相対パス、未取得の架空URL、読者が開けない `paper/` のパスを掲載しない。任意のHTMLやJavaScriptが動作する前提で書かず、Zenn公式の埋め込み機能を使う。

最後にZennプレビューを開き、数式、折りたたみの閉じ忘れ、図・キャプション、脚注、コードの表示を確認する。静的な文字列検索だけでは、KaTeX表示や数学の正しさを保証できない。
