# 論文から Zenn 記事を書く

リポジトリの `AGENTS.md` を読み、今回の明示的な希望を優先する。新規執筆では [author-style.md](references/author-style.md) を読む。必要なら近い題材の既存記事を作風の参考にするが、本文の出典や読者の前提にはしない。限定的な修正では該当箇所と前後の論理を中心に読む。

## 文献から中心的な問いを見つける

1. `paper/` を調べ、依頼に対応する文献、付録、図を特定する。Markdown や TeX は検索し、PDF は本文の抽出とページ表示を使い分ける。図や崩れた式は原資料の表示で確かめる。
2. 問題設定、記号、目的関数、成立条件、主要結果、限界を整理する。中心となる主張は原論文の節・式・図へ戻れるよう作業中に控える。読者向け本文へローカルファイルパスを出典として貼らない。
3. 中心の問い・設計の理由・成立条件を理解するのに必要な数理を選ぶ。原論文の全式や一般的な導出を網羅せず、選んだ導出で原論文が必要な説明を省略している場合は補う。原論文の主張、自分で補った導出、直感的な解釈を区別する。ローカル資料に誤記や変換崩れを見つけたら、数学的な検算と公開原版の照合を行い、未照合のまま原論文自体の誤りと断定しない。出典にない定理・数値・図の内容を補作しない。
4. 補足や引用には原論文の公開版・著者の実装・関連論文などの一次資料を優先する。作者の過去記事より正確で分かりやすい外部資料があれば積極的に選ぶ。対象文献が不明、重要な付録がない、方向性が複数あり決められない場合は短く質問する。著者の個人的経験や実験結果を創作しない。

記事は対象論文ごとに独立して読めるよう、必要な定義や前提を本文に含める。投稿順に沿った文脈を作らず、「これまで解説した〜」「前回の記事では〜」などと書かない。作者の過去記事は原則として引用せず、紐づけは作者から依頼された場合に行う。関連研究の比較は、その研究自体の一次資料を根拠に説明する。

脚注は出典の提示や短い補足に積極的に使う。手法名や文献の初出を目安に、原論文・公式資料への直接リンク、または書誌情報とリンクを含む脚注を添え、読者が根拠へたどれるようにする。主論文以外の比較手法にも出典を付ける。

## 6章に論理を組み立てる

第1章は `はじめに`、第6章は `さいごに`。第2〜5章は各3節まで。以下は配置の例であり、毎回同じ章題を使うテンプレートではない。

| 章 | 読者が理解すること |
| --- | --- |
| 1. はじめに | 従来の考え方では何が説明できず、この論文を読む意味は何か |
| 2. 問題設定と着眼点 | 従来の方法の何が問題で、何を変えるのか |
| 3. 手法と設計の理由 | どのような仕組みで、なぜその設計を選ぶのか |
| 4. 設計の意味と成立条件 | どんな見方が得られ、どの条件でその説明が成り立つか |
| 5. 実験と限界 | どの観察がどの主張を支え、何までは言えないか |
| 6. さいごに | 当初の問いへの答えと、手法を越えて持ち帰れる見方 |

四つの本論章の中で、前提・設計・実験・考察の因果関係を保つ。独立した理論章や一般論の導出を必須にせず、論文の中心に合わせて配置する。比較手法ごとに章を増やしたり、実験を網羅するために細分化したりしない。中心に必要な結果を選び、理解に役立つ補足だけを折りたたみに残す。内容上の例外が必要なら理由と代案を示す。既存記事の部分修正では、依頼なく全体を6章へ再編しない。

## 数理と思想を本文にする

- 先に「この数理が、どの思想・設計判断・成立条件の理解に必要か」を確かめる。文章や原論文の図で十分に伝わる操作の数式化、記号の列挙、中心に寄与しない一般的な損失・勾配・漸化式などの展開を追加しない。式の多さを深い理解の指標にしない。
- 採用した数式の記号は初出で定義し、ベクトル・行列の次元、添字の範囲、期待値を取る分布、最適化する変数を理解に必要な範囲で明らかにする。
- 必要な導出は「定義 → 代入 → 展開・整理 → 結果 → 意味」を追えるように書く。「計算すると」「自明」で必要な中間計算を飛ばさない。等号と近似を使い分け、Taylor 展開を使うなら展開点・次数・捨てた項・成立条件を示す。数式を絞ることと、残した数理の説明を省くことを混同しない。
- 中心となる導出と解釈は本文に置く。必要だが長い補助計算は `:::details` に収め、何を示す補足か分かるようにする。不要な数理は折りたたみへ移すのではなく削る。
- 数式の直後に、その結果が設計・評価・理解に何をもたらすか説明する。幾何的な直感は、その式のどこに対応するか結びつける。
- 図表も中心の議論に必要なものだけ選ぶ。原論文の図はスクリーンショットで示し、作者が用意したものを優先する。補足可視化が必要なら Python の matplotlib / seaborn を使い、コードを残す。原図の描き直し、画像生成AI、Mermaidでの図の新規作成は行わない。表はMarkdownで書き、資料中の図表をすべて掲載しない。図・GIFは各ファイル3 MB以内とし、本文で読み方と主張との対応を説明する。配置と確認の手順は運用skillの「図を準備する」に従う。
- 実験ではデータ、比較条件、評価指標、予算など解釈に必要な条件を添える。実験で支持された説明を、証明済みの一般則と書かない。
- 「さいごに」は要約だけで終わらせない。何を最適化・保存・比較する問題と捉え直したのか、その思想を本文の根拠と限界につなげる。根拠のない壮大な哲学を後付けしない。

KaTeX、折りたたみ、引用、図の書式には [Zenn 記法メモ](../zenn-article-workflow/references/zenn-markdown.md) を使う。ファイル生成や図の配置が必要なら [zenn-article-workflow](../zenn-article-workflow/SKILL.md) を読む。

## 作者と改稿する

初稿を保存したら、記事のパス、中心に据えた問い、重要な未確定点、確認できた表示を簡潔に伝え、作者の指摘を受ける。本文作成の依頼を構成案だけで終えたり、章ごとの許可を必須にしたりしない。構成や相談だけを依頼された場合はその範囲に応じる。

指摘を受けたら、説明不足・過剰な数理や図表・論理の飛躍・事実誤認・文体・方向性のどれかを考え、該当箇所を具体的に直す。過剰という指摘には中心の理解への寄与を見直して削り、不足という指摘には必要な導出・定義・例・根拠を補う。波及する記号や図番号も整合させる。意味が複数取れる指摘だけ確認し、既に満たした希望を繰り返し聞かない。

記事ファイルを作成・変更した場合は、提出前に原資料との一致、数理・図表の必要性、採用した計算の妥当性、6章と節数、KaTeX表示、図表の読み方、出典、`published: false`（下書きの場合）を確認する。作者の満足やレビュー完了を、公開操作へ自動的につなげない。
